# 디자인 기록 — shadcn 스타일 전환 (1안) + React 이관 경로 (2안 대비)

작성 2026년 9월 1일 · 중심 세션. 사용자 결정: "프로토타입은 1안(스타일만 입히기), 단 2안(React+shadcn)으로 나중에 대체 가능하게".

## 1. 무엇을 했나

- **ui.css 신설** — 화면들이 쓰는 모든 색·반경·그림자를 shadcn/ui의 시맨틱 토큰 이름(--background, --card, --primary, --secondary, --muted-foreground, --border, --ring, --radius …)으로 한 곳에 모았다. 값의 원본은 작업지침.md 브랜드 팔레트 그대로 — **계약(다크 팔레트, 반경 16px, 절제된 톤)은 바뀐 게 없다.** 다크/라이트는 :root[data-theme]로 토큰만 갈아끼운다.
- **화면 5종 리스타일** — 각 화면의 하드코딩 색을 토큰 소비로 교체하고 shadcn 시각 언어(카드 = card 배경+1px border+radius+얕은 그림자, 주 버튼 = primary 44px 600, 외곽선/고스트 변형, 알약 배지, 15% 틴트 상태색)를 적용했다. **동작 코드(id/class/DOM/JS/문구)는 한 글자도 안 바꿈** — 리스타일 후 E2E 전체 루프와 M6 내장 시험 16/16이 그대로 통과.
- JS가 색을 직접 읽는 화면(M3 지도 원, M6 캐릭터 SVG)은 옛 변수 이름을 토큰의 별칭으로 연결해 스크립트 무수정으로 처리. 캐릭터 8색은 캐릭터 계약이라 실값 유지.

## 2. 2안(React+shadcn)으로 갈 때의 경로

이번 작업이 이관 비용을 미리 줄여 뒀다:

1. **토큰이 이미 shadcn 이름이다** — ui.css의 :root 블록을 shadcn 프로젝트 globals.css에 그대로 옮기면 테마가 끝난다 (반경 16px 계약은 tailwind.config borderRadius로).
2. **api.js·엔진.js는 프레임워크 무관 순수 JS** — React에서 그대로 import. 화면은 이 둘 위의 얇은 껍데기라는 구조가 유지되는 한, 다시 그리는 건 표시 계층뿐이다.
3. **컴포넌트 대응이 정해져 있다** — 카드→Card, 확인 시트→Drawer, 버튼 변형→Button variant, 배지→Badge, 입력→Input, 하단 탭→Tabs. ui.css 하단 "이관 각서"에 명시.
4. 이관 시점 권장: 예선 이후, 앱 포장(Capacitor) 착수와 함께. 그전에는 1안 구조가 시연·수정·배포 모두 가볍다.
