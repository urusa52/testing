# 기술 검증 기록 — 구도 매칭 인증

작성 2026년 8월 5일 · 외계인 찾기 프로젝트

지원서에 올린 사진 3장(벚꽃나무, 수족관 카페, 콘크리트 틈)을 실제로 OpenCV에 넣고 돌린 결과다. 사업계획서에 "구도 매칭으로 인증한다"고 쓴 부분이 실제로 되는지, 어디까지 되는지를 숫자로 남긴다.

---

## 1. 판정 원리

네 단계로 돌아간다.

1. **특징점 추출** — 사진에서 주변과 구별되는 지점을 뽑는다. 모서리, 무늬가 꺾이는 곳, 얼룩의 경계. 시험한 사진들에서 각 2,000개가 나왔다.
2. **기술자 생성** — 각 특징점 주변의 밝기 패턴을 숫자 배열로 요약한다. 색이 아니라 밝기 패턴이라 조명 변화에 강하다.
3. **짝짓기** — 두 사진의 기술자를 비교해 가장 가까운 것끼리 묶는다. 이 단계에는 우연히 비슷한 짝도 섞인다.
4. **기하 검증(RANSAC)** — 짝지어진 점들이 하나의 일관된 변환으로 설명되는지 확인한다. 우연한 짝은 제각각 다른 방향을 가리켜 여기서 탈락한다.

사용 알고리즘은 ORB(BSD 라이선스, 무료). SIFT도 2020년 3월 특허 만료로 상업적 사용이 자유롭다.

---

## 2. 핵심 발견 — 판정 기준이 두 개여야 한다

**일치 특징점 개수만으로는 "같은 대상"까지만 알 수 있다. "같은 각도"는 못 가린다.**

한 걸음 옆으로 비켜서서 찍어도 650개가 일치한다. 같은 벽을 찍었으니 당연한 결과다. 이 기준만 쓰면 반경 안에서 대충 그 방향으로 찍어도 통과하고, 서비스의 핵심인 "그 각도에 서야 한다"가 무너진다.

해결은 기하 검증에서 나온 변환 규칙을 한 번 더 분해하는 것이다. 원본 사진의 네 모서리를 그 규칙대로 옮겨보면, 같은 각도에서는 거의 직사각형이 유지되고 옆에서 찍었으면 사다리꼴로 찌그러진다. **찌그러진 정도 = 시점 차이.**

### 측정 결과 (콘크리트 틈 사진 기준)

| 상황 | 일치 특징점 | 시점 차이 | 판정 |
| --- | --- | --- | --- |
| 정답 자리, 다른 날 흐림 | 897개 | 3.1% | 인증 |
| 정답 자리, 역광 + 사람 지나감 | 433개 | 10.8% | 인증 |
| 한 걸음 옆 | 650개 | 20.8% | 각도 불일치 |
| 두 걸음 옆 | 7개 | — | 실패 |
| 완전 다른 각도 | 3개 | — | 실패 |

### 판별력

| 비교 | 검증 통과 특징점 |
| --- | --- |
| 같은 자리 재촬영 | 400~900개 |
| 완전히 다른 사진끼리 | 0~4개 |

격차가 매우 크다. 기준선을 낮춰 잡을 여유가 충분하다.

### 이것이 곧 난이도 다이얼

시점 차이 허용치가 게임 난이도가 된다. 15% 이내를 통과시키면 쉬운 문제, 8% 이내면 정밀한 문제. 기획서의 "난이도 등급제"가 실제로 무엇을 조절하는지가 여기서 확정됐다.

**판정 기준 (초안)**

| 조건 | 결과 |
| --- | --- |
| 일치 30개 이상 + 시점차 12% 이내 | 완전 인증 |
| 일치 30개 이상 + 시점차 12~25% | 부분 인증 (포인트 감액, "거의 맞았어요") |
| 일치 30개 미만 | 실패, 재시도 |

## 3. 계절·환경 변화 대응

### 시도했다가 버린 방법

계절 따라 변하는 영역(나뭇잎, 하늘)을 검출해 판정에서 제외하는 방식을 시험했다. 효과가 없었다.

| | 전체 사진 | 변하는 영역 제외 |
| --- | --- | --- |
| 벚꽃나무, 계절 변화 강함 | 438개 | 432개 |
| 콘크리트 틈, 계절 변화 강함 | 421개 | 418개 |

특징점 방식이 색이 아니라 밝기 패턴을 보기 때문이다. 잎 색이 바뀌어도 가지 구조는 그대로라 이미 알아본다. 영역 마스킹은 복잡도만 늘리고 얻는 게 없다. **채택하지 않는다.**

### 채택한 방법 — 정답 사진 누적

성공한 사람의 사진을 정답 후보에 계속 추가한다. 새 도전자는 원본 하나가 아니라 정답 세트 전체와 비교된다.

| 겨울에 도전한 사진을 무엇과 비교하는가 | 일치 |
| --- | --- |
| 봄에 찍힌 원본만 | 342개 |
| + 여름 정답 | 645개 |
| + 가을 정답 | 810개 |
| + 겨울 정답 | 884개 |

**2.6배 개선.** 그리고 이 구조가 기존 어뷰징 방어 규칙과 그대로 맞물린다. "서로 다른 3명이 풀어야 정식 승격"이라는 규칙에서 그 3장이 곧 다계절 기준 데이터가 된다. 시간이 지나 정답이 쌓일수록 정확도가 저절로 올라간다.

### 추가 장치

- **점수제 판정** — 성공/실패 이분법 대신 점수. 부분 인증 구간을 둬서 실패해도 진전이 느껴지게 한다.
- **임계값 자동 완화** — 시도는 많은데 오래 성공이 없는 문제는 기준을 단계적으로 낮춘다. 그래도 안 풀리면 출제자에게 유효성을 확인한다.

## 4. 어뷰징 방어 — 각 수단이 무엇을 막는가

> 공개본 안내 — 이 절은 원문에서 요약했습니다. 부정행위 방어의 세부 동작과 현재 미보완 지점은 공개 저장소에 싣지 않습니다.

보상이 걸린 인증이라 방어는 한 겹이 아니라 여러 겹으로 설계했다. 공개본에는 층의 구성만 적는다.

| 층 | 역할 |
| --- | --- |
| 앱 카메라 전용 (갤러리 업로드 차단) | 현장에서 찍은 사진만 입력으로 받는다 |
| 서버 챌린지 서명 | 문제를 연 뒤 촬영한 것만 유효하게 만든다 |
| GPS 반경 게이트 | 사진 비교 이전 단계에서 현장 방문을 확인한다 |
| 구도 매칭 | 반경 안이어도 그 각도에 서지 않으면 통과하지 못한다 |
| 서버 재검증 | 보상이 걸린 인증을 특징점으로 다시 확인한다 |
| 신뢰 등급·교차 검증 | 다계정 자작 보상을 막는다 |

각 층이 무엇을 막고 무엇을 남기는지, 남은 구멍의 크기를 어떻게 측정했고 어떤 순서로 메우는지는 비공개 설계 문서에서 다룬다. 측정 자체는 실제로 수행했고, 그 결과가 아래 5장 이후의 판단 근거가 된다.

## 5. 출제 단계 사전 검사

특징점이 부족한 사진은 애초에 문제로 쓸 수 없다. 등록 시점에 걸러야 한다.

| 조건 | 특징점 | 판정 |
| --- | --- | --- |
| 원본 | 2,000개 | 가능 |
| 심한 역광 | 2,000개 | 가능 |
| 야간처럼 어두움 | 1,712개 | 가능 |
| 초점 나감 | 385개 | 반려 |

기준선 400개로 잡으면 초점 나간 사진이 자동 반려된다. 조명 문제는 밝기 보정으로 대부분 흡수된다.

**출제 화면에 사전 검사 UI가 필요하다.** 기획서 초판에 없던 화면이다.

부적합한 소재도 명시한다. 계속 움직이는 대상(물, 흔들리는 잎만 있는 화면), 똑같은 무늬가 반복되는 벽, 깊이 차이가 매우 큰 장면.

## 6. 브라우저 실행 가능성

- OpenCV의 웹 빌드로 휴대폰 브라우저에서 실행된다
- 최초 로딩 약 9MB, 이후 판정에 1~2초
- 사진이 단말 밖으로 나가지 않아 서버 비용 0원, 개인정보 측면에서도 유리
- 카메라는 촬영 버튼 → 폰 기본 카메라 호출 방식. 파일로 받은 HTML을 폰에서 직접 열어도 작동한다

## 7. 실험의 한계

시뮬레이션은 사진 한 장을 디지털로 변형해 만들었다. 실제 재촬영에는 입체적 깊이 차이, 다른 카메라 노출, 움직인 물건이 더해지므로 **실제 수치는 이보다 낮게 나온다.** 수백 개가 아니라 수십 개 수준일 가능성이 높다.

다만 다른 사진끼리가 0~4개라는 점에서 판별 여유는 충분하다.

**다음 단계에서 실제 현장 사진으로 재측정하고 기준선을 확정한다.**

## 8. 기획서에 반영할 사항

1. 판정 기준을 두 개(일치 개수 + 시점 차이)로 명시
2. "난이도 등급제"를 시점 차이 허용치로 구체화
3. 정답 사진 누적 구조를 3-1 또는 2-2에 추가
4. 출제 화면에 사전 검사 단계 추가 (3-2 화면 흐름)
5. 어뷰징 방어에 서버 챌린지와 워터마크를 5겹·6겹으로 추가 (2-3)
6. 부분 인증 구간을 인증 결과 화면에 반영 (3-2)
