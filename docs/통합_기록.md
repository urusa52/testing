# 통합 기록 — 모듈 여섯을 한 앱으로

작성 2026년 9월 1일 · 중심 세션. 현황 문서 B-7의 통합 체크리스트 ①~⑥을 이행한 기록이다.
산출물은 `통합/` 폴더 한 벌: `api.js`(v1.4) · `엔진.js` · 프로토타입 M2~M6 다섯 화면.

## 1. 구조

```
통합/
├── api.js                      데이터 단일 통로 v1.4 (CONFIG 포함, 화면은 fetch 금지)
├── 엔진.js                     판정 엔진 한 벌 (ENGINE.init(config) — 임계값 하드코딩 0)
├── 프로토타입_M3_지도.html      홈. 하단 4탭(지도·도감·쿠폰·나) + 출제 떠 있는 버튼
├── 프로토타입_M4_상세.html      지도에서 ?id= 로 진입. 힌트·범위 좁히기·난수 발급
├── 프로토타입_M2_촬영인증.html  M4에서 ?id=&nonce= 로 진입. 판정·제출
├── 프로토타입_M5_출제.html      사전 검사 4종 → 등록 → "지도에서 확인"
└── 프로토타입_M6_도감.html      도감·쿠폰·나 (?tab= 으로 탭 지정 진입)
```

- 이동 규약은 설계 5.7 판정 5 그대로: **파일 분리 + `?id=` 주소 이동**, 난수 발급은 M4.
- M1 매칭엔진 페이지는 **의도적으로 통합하지 않았다**. 개발자 검증 도구라 사용자 동선에 없고, 임계값 현장 튜닝용으로 독립 파일이 오히려 맞다.

## 3. api.js v1.4 (v1.3.1에서 바뀐 것)

- `ME.solved`가 `[{questId, at}]` — 도감이 "언제 찾았는지"를 쓴다
- `CONFIG.engine` 신설 — 이미지·ORB·매칭·RANSAC·판정·GPS·정답 누적의 모든 임계값이 여기 한 곳
- `CONFIG.coupon.warnDays: 3` (설계 5.8 추가 판정 7)
- `getTheme/setTheme` — 테마를 세션 다리에 실어 화면 간 연속 (추가 판정 9)
- `invalidateCode` — 쿠폰 코드 만료 처리
- **세션 다리**: `sessionStorage['alien-proto-bridge']`에 `{theme, drafts, hints, solved}`.
  실서버의 Attempt/User 기록을 프로토타입에서 대신하는 것으로, 영구 저장이 아니라 탭 수명이다.
  실서비스 전환 시 이 다리를 지우고 `_load/_save`만 서버 호출로 바꾸면 된다.

## 4. 엔진.js

M1·M2·M5에 세 벌로 흩어져 있던 판정 코드를 IIFE 한 벌로. `ENGINE.init(API.CONFIG.engine)`으로 시작하며 파일 안에 숫자 임계값이 없다. 구성: Pipeline(정규화·이중 선명도 게이트·특징 추출·분포·자기유사), Matcher(비교·시점차), Judge(4구간+판정불가), Gps(6초 데드라인), questChecks(출제 3단계), buildBankItem/judgeAttempt(정답 누적·조기 종료), opencv 3중 CDN 로더. Mat 풀·`p.delete()` 정리 포함(버그점검 20260819의 누수 항목 재발 방지).

## 5. E2E 한 바퀴 (2026.9.1 통과)

Playwright(Pixel 7 에뮬레이션, 헤드리스 크로뮴)로 실제 사용자 동선 한 바퀴:

```
1. 출제 등록          OK — 새 문제 id 발급, 드래프트가 다리에 실림
2. 지도               11개 목록 + "내가 낸 문제" 배지 + 테마(light) 이어짐
3. 지도 → 상세        ?id=q02 진입, 문제 정보 렌더
4. 범위 좁히기        hints ["peek"] 기록 → 인증 이동 (난수 동봉)
5. 판정               뱅크 특징점 1330 → 검증 638, 시점차 0 → pass 100
   제출               submitAttempt 호출 확인, solved에 {questId:'q02', at:'방금'}
6. 도감               발견 3 (기대 3) · 테마 이어짐 · 스크립트 오류 0
```

시험 스크립트: `exp/e2e.js`(전체 루프), `exp/chain3.js`(M4→M2 저장소 연속성, 전 페이지 저장소 추적기 포함).

**디버깅에서 배운 것 (다음 사람을 위해):**

- 한때 "M2 도착 시 힌트가 사라진다"로 보였던 문제는 앱 버그가 아니라 **시험의 관찰 착시 두 겹**이었다.
  ① 다리 내용을 200자로 잘라 보고 있었는데 drafts의 사진 dataURL이 그 200자를 다 차지해 뒤의 hints가 안 보였다. 저장소를 눈으로 확인할 땐 원문 슬라이스가 아니라 **키 목록**으로 볼 것.
  ② `'발견!'` 텍스트 대기는 숨겨져 있는 판정 화면 마크업에 즉시 걸렸다(`textContent`는 display:none도 읽는다). 최소 연출 1.2초가 끝나기 전에 다음 단계가 실행돼 "제출 안 됨"처럼 보였다. 대기는 텍스트가 아니라 **실제 상태**(제출 훅 호출, `offsetParent`가 있는 버튼)로 걸 것.
- Playwright에서 한글 파일명은 percent-encoding이라 `waitForURL`에 `decodeURIComponent` 술어가 필요하다.
- opencv.js는 작업 환경에서 CDN이 막혀 라우트 가로채기로 로컬 사본을 물린다. 배포 코드는 3중 CDN 폴백이라 실환경에선 문제 없다.

## 6. 남은 것

- **선택 과제**: api.js `demoPhoto`의 SVG에 width/height와 질감을 넣으면 M2의 `questPhotoToCanvas` 보정 셈이 빠질 수 있다. 시연에는 영향 없음.
- 실기기 확인 3종(현황 A-3)과 M1 현장 시험은 사람 몫 그대로.
- 단일 페이지 병합 여부는 시연 시나리오 확정 후 (설계 5.7 판정 5 그대로).
