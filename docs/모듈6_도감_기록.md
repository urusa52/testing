## 1. 무엇을 만들었나

찾은 뒤에 남는 화면이다. M2에서 인증이 끝나면 사용자는 여기로 돌아온다. 세 개의 탭으로 나눴다.

| 탭 | 내용 | 보상 층 |
| --- | --- | --- |
| 도감 | 내 동네 안개 걷힌 정도, 문제 하나당 칸 하나. 찾은 칸은 외계인이 채워지고 못 찾은 칸은 실루엣 + ? | 1층 |
| 쿠폰 | 받은 쿠폰 목록, 일회용 사용 코드 화면(큰 글씨 + 초읽기 + 가게 확인 버튼) | 2층 |
| 나 | 한눈이 얼굴, 등급(신규/일반/신뢰) 사다리, 포인트, 내가 숨긴 장면 | 1~3층 |

도감 칸을 누르면 시트가 올라온다. 찾은 칸은 캐릭터와 장면 이름, 못 찾은 칸은 실루엣과 출제자 한 줄 힌트, 그리고 [찾으러 가기](M3·M4로 이어질 자리). 빈칸이 다음에 나갈 이유가 되게 하려면 빈칸에도 뭔가가 있어야 해서, 힌트와 지역명까지는 열어 뒀다. 이건 M3 지도가 이미 보여 주는 수준과 같다.

### 안개 연출

찾은 수 ÷ 전체 수만큼 왼쪽부터 걷힌다. 동네를 블록 열 개로 추상화해 그렸고 좌표도 지명도 쓰지 않는다. 문구는 "내 동네 안개가 20% 걷혔어요 / 아직 8곳이 흐려요. 한 곳만 더 찾으면 조금 더 밝아져요." 퍼센트를 남긴 이유는 이 숫자가 판정 내부값이 아니라 진행도 연출이기 때문이다(UI 원칙에서 감추라고 한 것은 inliers·시점차·점수다).

### 사용 코드 화면

시스템_설계 5.5 ③의 "후자"를 그대로 구현했다. 별도 점주 앱 없이, 사용자 화면에 네 글자 코드와 3분 초읽기 링을 띄우고 가게에서 확인 버튼을 누른다. 그 순간이 곧 과금 시점(사업계획서 5-1 ①)이다. 코드 글자는 헷갈리는 문자(0·O·1·I·2·Z·5·S·6·B·8)를 뺀 25자에서 뽑는다. 만료되면 코드가 사라지고 "가게 앞에서 다시 받아 주세요"로 바뀐다 — 미리 받아 두는 것을 막는 장치다.

## 2. 층 구조 (파일 안)

```
API        데이터 단일 통로 (v1.2 + M6 초안 3함수)
Alien      캐릭터 SVG 생성기 — A안 한눈이 / B안 동글이 8종 / C안 틈눈이 / 실루엣
View       도감·쿠폰·나 렌더 + 시트 + 토스트
Code       쿠폰 일회용 코드 (발급·초읽기·만료·사용 처리)
Dev        개발자 모드(버전 7회 탭) + 시연 도구
Tests      자동시험 16종
```

화면 코드는 `fetch`를 부르지 않는다. 계약을 말로만 지키지 않으려고 로드 시점에 `fetch`와 `XMLHttpRequest.open`을 감싸는데, API 층 안에서 나가는 통신은 세지 않고 **바깥에서 나간 것만** 센다. 자동시험 1번이 그 값이 0인지 본다 — 서버가 붙은 뒤에도 그대로 쓸 수 있는 검사다.

## 3. 캐릭터 규칙

방향은 프로젝트 확정안을 따랐다. A안(한눈이)이 메인·앱아이콘, B안(동글이) 계열 8종이 도감, C안(틈눈이)이 로딩.

12px에서 살아남게 하려고 규칙 세 개를 세우고 자동시험으로 강제했다.

- 눈 지름 ≥ 도형 폭의 30% (실제 33%) — 축소하면 눈 하나만 남아도 외계인으로 읽힌다
- 모든 무늬의 최소 두께 ≥ 6% (실제 6.7%) — 그보다 얇으면 12px에서 사라진다
- 무늬는 선이 아니라 덩어리, 색은 몸 색과 배경색의 대비로만 (라이트·다크 양쪽에서 같은 무늬가 보인다)

8종은 색 8개 × 무늬 8개가 모두 다르다: 크라운, 띠, 반쪽, 고리, 볏, 달, 줄, 이마판. 웃는 입·볼터치·반짝임은 넣지 않았다.

문제 id를 해시해 캐릭터를 배정한다. 서버가 정해 주지 않아도 어느 기기에서나 같은 문제엔 같은 외계인이 나온다. 문제가 8개를 넘으면 종이 반복된다(제안 3 참조).

## 4. 데이터 계약

쓴 것: `getConfig()`, `getMe()`, `getQuests()` — 표준 api.js v1.2 그대로.
M6에서 새로 쓴 것(표준에는 아직 없음, 파일 안에 초안으로 넣음):

```js
CONFIG.coupon = { codeTtlSec: 180, warnSec: 30, warnDays: 3 }
getMyCoupons()            → [{ id, shop, item, questId, status:'active'|'used', daysLeft|usedWhen, walk }]
issueCouponCode(couponId) → { couponId, code, ttlSec, expiresAt, issuedBy:'server' }
redeemCoupon(code)        → { ok:true, couponId } | { ok:false, reason:'expired' }
invalidateCode()          → 발급 취소 (화면을 닫거나 만료되면 호출)
```

`expiresAt` 검사와 `invalidateCode()`는 버그 점검에서 추가됐다. 이게 없으면 "만료됐어요"를 띄운 코드가 그대로 사용 처리된다. 프로토타입은 이 폰의 시계를 쓰지만 **서버가 붙으면 반드시 서버 시각 기준**이어야 한다(시스템_설계 5.5 ②).

시연·시험용으로 `API._demo`(도감 채움, 등급 전환, TTL 변경, 초기화)를 뒀다. 실서비스에서는 서버가 하는 일이라 이행 시 삭제 대상이다.

### 아직 확인 못 한 것

- 실기기(안드로이드 폰) — safe-area 여백, 탭바가 시스템 제스처 바와 겹치는지, 화면 유지 요청(wakeLock)이 실제로 먹는지. 초읽기 자체는 화면 꺼짐을 견디도록 고쳤고 시계를 200초 앞으로 밀어 확인했다
- 밝은 야외 조명에서 라이트 테마 대비 (코드 화면은 가게에서 보여 주는 화면이라 특히)
- 도감 문제가 100개일 때의 실기기 스크롤 성능 (렌더 자체는 9ms로 확인)

## 7. 오류가 났을 때

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 화면이 "불러오는 중"에서 멈춤 | `View.load()`에서 예외 | 부팅 오류 문구로 전환, 개발자 모드 로그에 원인 기록 |
| 코드가 안 나옴 | `issueCouponCode` 실패(만료·비활성 쿠폰) | 코드 화면을 닫고 "지금은 코드를 받을 수 없어요" 토스트 |
| 코드가 만료됨 | 3분 경과 | 코드를 지우고 [코드 다시 받기]로 버튼 교체 |
| 사용 처리가 안 됨 | 서버가 코드를 모름(재사용·만료) | 만료 처리로 되돌리고 재발급 유도. 버튼은 반드시 다시 활성화 |
| 사용 처리 도중 통신 끊김 | `redeemCoupon` 예외 | 버튼 복구 + "한 번만 다시 눌러 주세요" 토스트 (점검 5번) |
| 화면을 닫았다 다시 열었을 때 | 발급이 무효화됨 | 코드를 새로 받는다 — 미리 받아 두는 것을 막는 장치 |

버튼이 영구히 잠기는 경로가 없도록, 실패 경로에서도 `disabled`를 되돌린다(M5 점검에서 나온 교훈).

## 8. 중심 세션 제안

1. **api.js 표준에 쿠폰 계약 반영.** 위 4장의 `CONFIG.coupon` + 3함수를 표준 `api.js`에 넣고 v1.3으로 올리는 것을 제안한다. M6 파일 안의 초안은 그때 삭제하고 표준본을 불러 쓴다. 지금은 계약을 바꿀 권한이 없어 파일 안에만 뒀다.
2. **User.solved에 발견 시점.** 지금은 `solved:['q04','q06']`이라 도감에 "언제 찾았는지"를 쓸 수 없다. `[{questId, at}]`로 바꾸면 도감이 기록물이 된다("작년 가을에 찾은 자리"). 데이터 구조(시스템_설계 1장) 변경이라 중심 판단이 필요하다.
3. **캐릭터 종 수와 배정 주체.** 지금 문제 10개에서도 이미 두 쌍이 같은 외계인이다(q01·q09, q07·q10). 문제 100개면 한 종이 12~13번 반복된다. 두 갈래다. ① 8종을 '종족'으로 두고 반복을 의도로 삼는다(수집 대상은 장면, 캐릭터는 분류) ② Quest에 `characterId`를 두고 서버가 배정한다(희귀종 설계 가능, 데이터 구조 변경). 지금은 ①로 두되 id 해시로 결정적 배정만 보장해 뒀다.
4. **위성 C와의 관계.** 프로젝트에 `외계인_캐릭터안.svg`가 없어서(세션 산출물로만 남았다) A/B/C 방향 설명만 보고 새로 그렸다. 위성 C가 확정본을 내면 `Alien` 모듈의 도형 함수만 갈아 끼우면 되고, `indexFor`(결정적 배정)와 12px 규칙 세 줄은 유지하기를 권한다. 이번 시안은 `외계인_캐릭터_M6시트.svg`로 첨부했다.
5. **탭바를 앱 전체 네비게이션으로 쓸지.** M6에 도감/쿠폰/나 세 탭을 만들었는데, 통합하면 지도(M3)와 출제(M5)가 여기 붙는 게 자연스럽다. 다섯 탭이 될지, 지도를 홈으로 두고 출제를 떠 있는 버튼으로 둘지는 통합 설계 결정 사항이다.
6. **미발견 칸의 정보량.** 실루엣 + 지역명 + 출제자 한 줄 힌트까지 열어 뒀다. M3 지도가 이미 같은 수준을 보여 주므로 일관되다고 판단했지만, 도감에서는 더 가려야 한다면 지침을 달라.
7. **`CONFIG.coupon.warnDays` 추가.** 쿠폰 만료 임박 강조 기준(3일)이 화면 코드에 박혀 있던 것을 CONFIG로 옮겼다. 표준 api.js 반영 대상.
8. **핀치 확대 금지 재검토.** `user-scalable=no`가 M5와 공통이라 M6만 바꾸지 않았다. 지역 주민(고령층 포함)이 쓰는 앱이라 확대를 막는 게 맞는지 전 모듈 차원의 판단이 필요하다.
9. **테마 선택 저장·시스템 설정 따르기.** 지금은 새로고침하면 다크로 돌아온다. 브라우저 저장을 프로토타입에서 쓰지 않기로 해서 남겼고, 호스팅 이후 붙이면 된다.
10. **점주 확인 방식의 다음 단계.** 프로토타입은 사용자 화면의 버튼을 점주가 누르는 방식이다. 점주가 자기 폰에서 코드를 입력하는 방식으로 갈 때 코드 자릿수(지금 4자)와 유효시간(3분)을 확정해야 하고, 그 값은 `CONFIG.coupon`에 이미 자리를 잡아 뒀다.
