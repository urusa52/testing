## 1. 이 모듈이 하는 일

M1 판정 엔진을 사용자 흐름으로 감싼 첫 사용자 대면 화면. 문제 보기 → 탐색 → 촬영 → 판정 연출 → 보상까지의 한 줄이 실제로 동작한다.

처음 적용된 계약 두 개:
- **api.js 단일 통로** (시스템_설계 5.5) — 화면 코드는 `api` 객체 밖의 데이터를 모른다. 지금은 내장 데이터를 돌려주고, 서버가 생기면 이 객체 내부만 fetch로 바뀐다.
- **UI 원칙: 숫자는 개발자 모드로** (시스템_설계 6장) — 사용자 화면에는 문구·색·연출만. 원시 수치는 버전 표기 7회 탭으로 여는 패널에만.

## 2. 층 구조

```
api        데이터 단일 통로 (내장 → 나중에 서버)
CONFIG~Engine   M1 엔진 이식 (입출력 계약 불변)
Stage      판정 키(pass/part/near/fail/void/gps) → 연출 변환표
Flow       화면 상태 전환 (boot → setup → quest → hunt → result)
Dev        개발자 모드 (수치·로그·임계값 슬라이더)
```

아래로만 의존한다. Stage 변환표가 이 모듈의 심장인데, 판정 엔진이 뱉는 숫자와 사용자가 보는 문구를 잇는 유일한 다리다. 문구를 바꾸고 싶으면 이 표만 고친다.

## 3. 이 모듈에서 내린 결정

1. **판정 연출 최소 1.2초.** 엔진이 0.2초 만에 끝나도 "장면을 살펴보는 중…"을 1.2초는 보여준다. 즉답은 판정을 가볍게 보이게 하고, 잠깐의 기다림이 결과의 무게를 만든다.
2. **CONFIG 비동결.** M1은 Object.freeze였지만 M2는 개발자 모드 슬라이더가 임계값을 실시간 조정해야 해서 동결을 풀었다. "임계값은 CONFIG 한 곳" 계약은 유지.
3. **GPS 기본 생략 (프로토타입).** file://로 열면 GPS가 차단되는 환경이 있어 기본값을 생략으로 두고, 개발자 모드에서 켤 수 있게 했다. https 호스팅 후 기본값을 뒤집는다.
4. **시연 준비 화면.** M5(출제)가 아직 없어서, 문제 사진이 없으면 등록 화면을 먼저 보여준다. M5가 완성되면 이 화면은 제거된다.
5. **외계인 캐릭터 자리.** 성공 연출의 아이콘 영역(stage-icon)이 캐릭터가 들어갈 자리다. 지금은 임시 기호. v2에서 교체.

## 5. 오류 대응 가이드 (증상 → 원인 → 확인 위치)

| 증상 | 유력 원인 | 확인·조치 |
| --- | --- | --- |
| "지금은 주변을 살필 수 없어요"에서 멈춤 | OpenCV CDN 3곳 모두 실패 (인터넷 없음/차단) | 인터넷 연결 후 새로고침. 그래도 안 되면 다른 네트워크 |
| 부팅이 매우 느림 | 최초 1회 9MB 다운로드 | 정상. 두 번째부터 캐시 |
| 정상 사진이 "흔들렸어요"로 반려 | minSharpness가 환경 대비 높음 | 개발자 모드 → sharpness 수치 확인 → 슬라이더로 하향 |
| 정답 자리인데 "거의 다"만 나옴 | viewShiftTol이 장면 대비 좁음, 또는 원본과 계절·조명이 크게 다름 | 개발자 모드 → viewShift 확인. 20% 안팎이면 슬라이더 완화. 뱅크에 새 정답 추가가 근본 해결 |
| 엉뚱한 사진이 통과 | minInliers가 낮음 | 개발자 모드 → inliers 확인 → 슬라이더 상향 |
| 판정이 5초 넘게 걸림 | 저사양 기기 + 뱅크 다수 | 개발자 모드 elapsed 확인. CONFIG.orb.nFeatures 2000→1500 하향 검토 |
| 촬영 버튼이 카메라를 안 염 | 일부 브라우저의 capture 미지원 | "저장된 사진으로 도전" 경로로 우회 가능 |
| GPS 켰는데 항상 차단 | file:// 비보안 컨텍스트 | https 호스팅으로 열기 (점검기록 문서 참조) |
| 판정 중 오류 알림 | 메모리 부족 등 | 개발자 모드 로그의 마지막 줄 확인 후 중심 세션에 보고 |

모든 판정의 원시 수치와 처리 로그는 개발자 모드(버전 표기 7회 탭)에 남는다. 오류 보고 시 이 패널 스크린샷 한 장이면 진단 가능하다.
