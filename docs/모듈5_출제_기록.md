## 1. 이 모듈이 하는 일

사용자가 장면을 촬영해 문제로 등록하는 화면. 촬영 즉시 **사전 검사 4종**을 단말에서 돌려 문제로 쓸 수 없는 사진을 등록 전에 걸러낸다. 통과하면 반경·난이도·힌트를 설정하고 '검증 중' 상태로 접수된다 (3명 인증 시 정식 승격 — 시스템_설계 3장).

M2의 임시 "시연 준비" 화면을 대체하는 정식 출제 흐름이다.

## 2. 사전 검사 4종과 근거 실험

| 검사 | 지표 | 기준 | 근거 (실측) |
| --- | --- | --- | --- |
| ① 선명도 | 라플라시안 분산 (CLAHE 이전) | ≥ 40 | 정상 340~5,700 vs 심한 흐림 1.7 |
| ②-1 단서량 | ORB 특징점 수 | ≥ 400 | 초점 나감 385 (기술검증 실험 6) |
| ②-2 단서 분포 | 6×6 격자 변동계수 | ≥ 0.5 | **이번에 신설.** 노이즈 벽 0.27~0.30, 타일 벽 0.35 vs 실제 장면 0.85~3.15 |
| ③ 자기 유사성 | 좌/우 반쪽 상호 매칭률 | ≤ 2.0% | **이번에 확정** (모듈1 미결 항목). 정상 0.0~0.4% vs 반복 무늬 4.1~8.4% |

### 검사 ②-2가 생긴 경위 — 시험이 잡아낸 구멍

특징점 "개수"만 검사하는 원래 설계가 자동 시험에서 뚫렸다. 무늬 없는 벽도 센서 노이즈가 조명 보정(CLAHE)에서 증폭되면 특징점 1,200~1,800개가 나온다. M1의 흐림 검출 때와 같은 함정(CLAHE의 노이즈 증폭)이 세 번째로 나타난 것.

가벼운 블러로 노이즈를 죽이는 방법을 먼저 시험했으나 실패(블러 후에도 1,774개). 대신 **분포**로 잡았다. 노이즈 특징점은 화면 전체에 균일하게 퍼지고, 실제 장면의 특징점은 구조가 있는 곳에 몰린다. 격자별 개수의 변동계수로 재면 겹치지 않게 갈린다. 부수 효과로 반복 타일 벽도 이 검사에 걸린다 (자기 유사성 검사와 이중 방어).

현실 수준 점검: 깨끗한 민무늬 벽(노이즈 σ3)과 그라데이션 하늘은 특징점 0개로 ②-1에서, 낮 촬영 수준(σ6)은 선명도 38로 ①에서 걸린다. ②-2가 실제로 막는 것은 야간 고감도 촬영의 거친 입자 사진이다.

## 3. 반려는 진단이 아니라 처방으로

반려 사유를 숫자가 아니라 다음 행동으로 말한다 (UI 원칙).

| 검사 실패 | 사용자에게 |
| --- | --- |
| 선명도 | "사진이 조금 흐려요 — 초점을 맞추고 잠시 고정한 뒤 찍어 보세요" |
| 단서량·분포 | "단서가 부족해요 — 무늬·모서리·경계가 많은 쪽으로 조금만 움직여 볼까요?" |
| 반복 무늬 | "위치를 특정하기 어려워요 — 반복이 깨지는 부분(모서리, 금, 얼룩)을 화면에 넣어 보세요" |

검사 과정 자체를 체크리스트 연출로 보여준다("또렷하게 찍혔나요 → 단서가 충분한가요 → 위치를 특정할 수 있나요"). 검사가 즉시 끝나도 단계당 0.35초를 보여줘서 앱이 사진을 진지하게 봤다는 감각을 만든다.

## 4. 계약 반영·확장

- **api.js v1.2**: `createQuest(payload)` 추가, `CONFIG.quest` 검사 임계값 추가. 표준 파일 갱신 완료
- 등록 시 사진 원본은 전송하지 않는다 — 특징점 요약·설정만 (개인정보 계약)
- 사생활 자기확인 체크(얼굴·번호판·집 내부 없음 + 위험 장소 아님) 필수 — 시스템_설계 3장 검사 3의 프로토타입 구현 (자동 검출 모델은 v2)
- 위치는 확보 시도 후 실패해도 진행 (프로토타입 한정. 실서비스에선 필수)
- 라이트/다크 두 테마 (작업지침 규칙 6 갱신분 첫 적용), 해요체

## 5. 모바일 앱 전환 대비 (이번 요청 반영)

**경로: 웹 → PWA → 스토어 앱.** 코드를 다시 짜지 않는 경로다.

1. **지금 (M5부터 적용)**: PWA 메타 준비 완료 — theme-color, 홈 화면 설치용 매니페스트, 상태바 스타일, 안전 영역(노치) 대응 패딩. 홈 화면에 추가하면 주소창 없이 앱처럼 열린다
2. **https 호스팅 시**: 서비스워커 한 파일 추가 → 오프라인 캐시 + 정식 PWA. GPS 차단 문제도 함께 해결
3. **스토어 등록 시**: TWA(플레이스토어) 또는 Capacitor(양대 스토어)로 포장. 웹 코드가 그대로 앱 껍데기 안에서 돈다. Capacitor를 쓰면 카메라·GPS를 네이티브 API로 교체 가능

모든 모듈이 서버 없이 단말에서 돌아가는 구조라 이 경로에 걸리는 것이 없다. 통합 시점에 M1~M4에도 같은 PWA 메타를 적용한다.

## 7. 오류 대응 가이드

| 증상 | 원인 후보 | 확인·조치 |
| --- | --- | --- |
| 정상 사진이 "단서 부족" 반려 | 어두운 실내, 원거리 풍경(구조가 한 구석에만) | 개발자 모드 → features·spread 확인. spread 0.5 부근이면 실측 후 기준 하향 검토 |
| 반복 무늬가 통과됨 | 반복 주기가 화면 절반보다 큼 (좌우 대조가 못 잡음) | selfSim 수치 확인. 상/하 분할 검사 추가는 v2 후보 |
| 야간 사진이 계속 반려 | 고감도 노이즈 → spread 낮음 | 의도된 동작. 야간 출제 제한 정책(시스템_설계 3장)과 일치 |
| 검사가 5초 이상 | 저사양 기기 | 개발자 모드 elapsed 확인. 특징점 2000→1500 하향 |
| 홈 화면 추가가 안 보임 | file:// 로 열면 설치 불가 | https 호스팅 후 가능 (5장 경로) |
