# 모듈 3 — 지도 화면: 구조와 시험 기록

작성 2026년 8월 19일 · M3 작업 세션 · 외계인 찾기 프로젝트
설계·계약 변경 권한 없음. 바꿔야 할 것은 이 문서 끝 "중심 세션 제안"에 모아 두었다.
산출물: `프로토타입_M3_지도.html` (단일 파일), `api.js` (분리 보관본)

## 0. 이 모듈이 한 일

지도에서 문제를 고르는 화면을 만들었다. 함께 나온 것이 하나 더 있는데, **`api.js`가 여기서 처음 생겼다.** 원래 계획은 M2에서 도입하는 것이었지만 M3를 먼저 만들기로 하면서 순서가 바뀌었다. 그래서 이 문서는 지도 기록인 동시에 데이터 통로 계약서 역할을 한다.

빌드 순서를 바꾼 근거는 시스템_설계 5장의 "지도는 독립적이라 언제든 붙일 수 있다"이다. 계약 위반은 아니다.

## 1. 파일 구조

단일 HTML 안에 세 덩어리가 순서대로 들어 있다. 위에서 아래로 의존하고, 아래가 위를 모른다.

```
프로토타입_M3_지도.html
├── [스타일]  디자인 토큰 (라이트/다크 두 세트) + 화면 CSS
├── [Leaflet] 라이브러리 내장 (오프라인에서도 파일 하나로 열림)
├── [api.js]  <script id="api-js"> ... </script>
│              ← 이 블록을 그대로 잘라내면 별도 api.js 파일이 된다
├── [MapAdapter] 지도 라이브러리를 감싼 층. 카카오맵 교체 지점
└── [App]     화면 로직. API와 MapAdapter만 알고 Leaflet을 모른다
```

App이 Leaflet을 직접 부르는 곳은 한 군데도 없다. 카카오맵으로 갈아탈 때 `LeafletAdapter`를 `KakaoAdapter`로 바꾸고 같은 함수 6개(`init` / `setTileStyle` / `drawQuest` / `removeQuest` / `focusQuest` / `drawMe`)만 채우면 App은 손대지 않는다.

## 2. api.js 계약

화면 코드는 직접 fetch 하지 않는다 (시스템_설계 5.5장). 프로토타입 단계에서는 내장 JSON을 Promise로 감싸 돌려주고, 서버가 생기면 이 파일의 함수 본문만 바꾼다.

| 함수 | 돌려주는 것 | 쓰는 곳 |
| --- | --- | --- |
| `getQuests()` | 지도용 문제 목록 | M3 |
| `getQuest(id)` | 문제 하나 + `features` (출제 사진 특징점) | M2, M4 |
| `getMe()` | 계정, 포인트, 도감 | M6 |
| `getConfig()` | 임계값 전부 (CONFIG 한 곳) | M1, M2, M5 |
| `issueNonce(questId)` | 일회용 난수 | M2 |
| `submitAttempt(questId, payload)` | 결과 접수 | M2 |

### 개인정보 계약이 코드 형태로 박혀 있다

`getQuests()`가 돌려주는 객체에 **`answer_gps`가 아예 없다.** 숨기는 게 아니라 존재하지 않는다. 서버가 내려보내지 않으니 클라이언트가 가질 방법이 없고, 화면 개발자가 실수로 노출시킬 여지도 없다.

`center`는 실제 촬영 위치가 아니라 그것을 포함하는 임의 원의 중심이다 (시스템_설계 1장). 지도에 그려지는 것은 이 임의 원뿐이다.

자동 시험으로 확인했다 — 목록 10개 전부에 `answer_gps` 키 없음.

### CONFIG에 지도용 값 3개를 추가했다

```
map: { fadeFar: 1500, fadeNear: 150, defaultZoom: 15 }
```

기존 판정 임계값(`inliersMin`, `viewShiftMax`, `verdict`)은 건드리지 않았다. 지도 표현용 값도 같은 CONFIG 한 곳에 두는 것이 원칙 6과 맞다.

## 3. 화면 규칙

### 가까울수록 또렷해진다

내 위치와 문제 반경 중심 사이 거리(하버사인)를 재서 투명도와 흐림을 정한다.

```
1500m 이상 → 투명도 0.18, 흐림 2.6px   (거기 뭔가 있다는 것만 보임)
 150m 이하 → 투명도 0.95, 흐림 0px     (또렷)
그 사이     → 비례
```

숫자는 화면에 나오지 않는다. 목록의 거리 표시는 `바로 여기 / 아주 가까움 / 가까움 / 조금 멈 / 멀리` 다섯 단계 말뿐이다. UI 원칙(시스템_설계 6장) 그대로다.

### 상태별 표현

| 상태 | 표현 |
| --- | --- |
| 정식 (live) | 실선 원 + 속이 찬 마커, 민트 |
| 검증 중 (review) | 점선 원 + 속이 빈 마커, 앰버 배지 |
| 휴면 (dormant) | 회색, "찾으러 가기" 버튼 비활성 |
| 내가 찾은 것 | 블루 + "찾음" 배지 |

내 위치는 속이 빈 이중 링으로 그렸다. 문제 마커(속이 찬 원)와 형태가 달라야 헷갈리지 않는다.

### 개발자 모드

브랜드 이름 7회 탭 또는 `?dev=1`. 여기서만 좌표, 반경 m, 거리 m, status, viewShiftMax, 시도/성공 수, 임계값이 보인다. 현장에서 값을 확인하는 도구다.

## 4. 지도 타일

라이브러리는 Leaflet, 타일은 CARTO를 쓴다. OSM 표준 타일은 색이 많고 상호명이 빽빽해서 반경 원과 마커가 묻힌다. 단순화된 회색 지도 위에서는 원이 그대로 읽힌다.

| 테마 | 타일 | 주소 |
| --- | --- | --- |
| 다크 | CARTO Dark Matter | `dark_all` |
| 라이트 | CARTO Positron | `light_all` |

API 키가 필요 없고, 저작자 표시(OpenStreetMap + CARTO)를 화면 하단에 넣었다. 무료 사용에는 트래픽 제한이 있으므로 정식 서비스 전 카카오맵 전환 또는 유료 전환이 필요하다. 타일 주소는 `TILES` 상수 한 곳에 모아 두었다.

## 5. 시험 결과

헤드리스 브라우저(Chromium, 390×844, 위치 권한 허용, 좌표 36.6015/127.2955)로 자동 확인했다.

| 항목 | 결과 |
| --- | --- |
| 문제 10개 지도·목록 표시 | 통과 |
| 내 위치 기준 거리순 정렬 | 통과 |
| 거리별 또렷함 차이 | 통과 (원경 흐림 2.6px → 근경 0px) |
| **사용자 화면 숫자·좌표 유출** | **없음** (정규식 검사: 소수 좌표, `m` 단위, 점수 표기 0건) |
| 문제 선택 → 상세 카드 | 통과 |
| 선택 시 반경 원이 시트에 가리지 않음 | 통과 (하단 여백만큼 보정) |
| 테마 전환 (다크 ↔ 라이트) | 통과, 타일도 함께 교체 |
| 개발자 모드 7회 탭 진입 | 통과 |
| 스크립트 오류 | 없음 |

타일 이미지는 작업 환경의 외부 접근 제한으로 내려받지 못했다. 지도 배경 그림이 실제로 뜨는지는 **일반 브라우저에서 열어 확인해야 한다.** 타일 외의 모든 로직은 위와 같이 확인됐다.

### 고치면서 발견한 것 3개

1. 지도에 붙지 않은 `L.circle`은 `getBounds()`를 못 쓴다 → 좌표에서 직접 사각 범위를 만들었다
2. 선택한 문제로 지도를 옮기면 하단 시트에 가려 아무것도 안 보였다 → 시트 높이만큼 아래 여백을 주고 반경 원 전체가 들어오게 맞췄다
3. 라이트 테마에서 "뒤로" 버튼 글씨가 배경과 같은 색이 됐다 → 주버튼 규칙이 보조버튼까지 덮고 있었다

## 6. 아직 안 한 것

- 문제가 많아졌을 때의 묶음 표시 (클러스터링). 시드 10개에서는 필요 없다
- 지도 이동에 따른 목록 갱신. 지금은 내 위치 기준 고정 정렬이다
- "찾으러 가기"가 M2로 연결되는 부분. 지금은 난수를 발급받고 안내 문구만 띄운다
- 시드 좌표는 조치원 실제 지점의 **근사값**이다. 현장 촬영 후 실제 좌표로 교체해야 한다

## 7. 중심 세션 제안

이 모듈을 만들면서 계약과 어긋나거나 계약에 없던 것을 정해야 했던 지점들이다. 결정은 하지 않았고, 코드는 아래 상태로 두었다. 채택/기각을 정해주면 그에 맞춰 고친다.

### 제안 1 · 디자인 토큰을 라이트/다크 두 세트로

작업지침 규칙 6은 다크 단일이다. 사용자가 회녹색 계열 팔레트를 지정하면서 두 테마를 모두 지원하기로 방향이 잡혔고, M3는 그 전제로 만들어져 있다. 규칙 6을 아래 표로 확장하는 안이다.

| 변수 | 다크 (기존) | 라이트 (신규) | 쓰임 |
| --- | --- | --- | --- |
| `--bg` | `#111319` | `#E0E2DB` | 화면 배경 |
| `--surface` | `#1A1D26` | `#F4F5F1` | 카드, 시트 |
| `--surface-2` | `#232733` | `#D2D4C8` | 눌림·선택 상태 |
| `--line` | `#2E3341` | `#B8BDB5` | 경계선 |
| `--text` | `#EDEFF5` | `#252B29` | 본문 |
| `--text-dim` | `#9AA3B2` | `#5F7470` | 보조 문구 |
| `--mint` | `#8FE6C4` | `#2E7D64` | 성공·주행동 |
| `--blue` | `#9FD4FF` | `#2F6C93` | 정보·이미 찾은 것 |
| `--amber` | `#FFD98E` | `#8A6520` | 주의·검증 중 |

라이트 팔레트 출처는 회녹색 계열(E0E2DB / D2D4C8 / B8BDB5 / 889696 / 5F7470)이다. 의미색 3종은 밝은 배경에서 대비가 나오도록 같은 색상을 어둡게 낮춘 값이다. 채택하면 M1·M2 프로토타입도 같은 구조로 맞춰야 한다 (색 변수만 바꾸는 수준).

기각하면 M3에서 라이트 테마를 걷어내고 다크 단일로 돌리면 된다. 토글 버튼과 `TILES.light` 항목만 빼면 끝이다.

### 제안 2 · api.js 계약이 두 벌이다 — 통일 필요

M2(`프로토타입_M2_촬영인증.html`)에도 `api` 객체가 있고, M3의 `api.js`와 모양이 다르다. "api.js 단일 통로"가 계약인데 통로가 둘인 상태다. 지금은 두 화면이 따로 돌아서 증상이 없지만 통합 시점에 반드시 부딪힌다.

| | M2의 `api` | M3의 `api.js` |
| --- | --- | --- |
| 문제 조회 | `getQuest()` — 데모 1개 고정 | `getQuest(id)` + `getQuests()` 목록 |
| 결과 제출 | `submitAttempt(result)` | `submitAttempt(questId, payload)` |
| 난수 발급 | 없음 | `issueNonce(questId)` |
| 임계값 전달 | 파일 안 `CONFIG` 전역 | `getConfig()` |

M3 쪽 형태를 권한다. 문제가 여러 개인 목록을 다룰 수 있고, 난수 발급 자리가 있고, 임계값을 `getConfig()`로 내보내 CONFIG 한 곳 원칙이 파일 경계를 넘어서도 지켜진다. M2는 데모 문제 1개 전제라 지도가 붙는 순간 버티지 못한다. 다만 M2의 판정 엔진 이식분과 Stage 변환표는 그대로 살릴 수 있고 api 호출부만 바꾸면 된다.

### 제안 3 · 임계값 표기를 퍼센트로 통일

M1·M2는 `viewShiftTol: 12` (퍼센트), M3의 api.js는 `viewShiftMax: 0.12` (비율)로 썼다. 엔진 원본과 개발자 모드 슬라이더가 퍼센트 기준이므로 **M3의 api.js를 퍼센트로 고치는 쪽**이 파장이 작다. 반대로 가면 M1·M2 엔진과 슬라이더를 다 건드려야 한다.

### 제안 4 · 지도 타일 제공자를 계약에 추가

CARTO 타일(다크 = Dark Matter, 라이트 = Positron)을 썼다. API 키가 필요 없고 저작자 표시만 넣으면 되지만 무료 사용에 트래픽 제한이 있다. 시스템_설계 5장의 M3 항목이 "Leaflet + OpenStreetMap"으로 되어 있어 실제와 다르다. 타일 주소는 `TILES` 상수 한 곳에 모아 두었고 어댑터 구조라 교체는 한 줄이다.

### 제안 5 · CONFIG에 지도용 값 3개를 추가했다

```
map: { fadeFar: 1500, fadeNear: 150, defaultZoom: 15 }
```

기존 판정 임계값은 건드리지 않았다. 지도 표현용 값도 같은 CONFIG 한 곳에 두는 것이 원칙 6과 맞다고 보고 넣었는데, 판정용과 표현용을 섞지 않는 편이 낫다면 분리한다.

### 제안 6 · 현황 문서 갱신이 필요하다 (중심 세션 소관)

`프로젝트_현황과_계획.md`는 중심 세션만 고치므로 손대지 않았다. 반영이 필요한 것:

- 완료 목록에 M3 (`프로토타입_M3_지도.html`, `api.js`, 이 문서) 추가
- "다음 할 일 B" 6번 M3 제거. M2도 이미 완료된 상태로 보이므로 4번도 확인 필요
- 사용자 직접 항목에 "M3 지도 실기기 확인" 추가 — 타일이 실제로 뜨는지는 일반 브라우저에서만 확인 가능
- 사용자 직접 항목에 "촬영 지점 좌표 확보 → M3 시드 좌표 교체" 추가

### 제안 7 · 프로젝트 설정의 지침 텍스트가 문서와 어긋난다

프로젝트 설정에 들어 있는 지침 텍스트는 `작업지침.md`와 별개로 보관되는데, 지금 그쪽에는 다크 단일 토큰과 "M3를 만들어라"는 위성 B 프롬프트가 남아 있다. 새 세션은 설정 지침을 먼저 읽으므로, 문서를 갱신할 때 설정 쪽도 같이 맞춰야 한다. 이건 도구로 고칠 수 없고 사람이 설정 화면에서 바꿔야 한다.
