# 외계인 찾기

동네의 특이한 '장면'을 사진으로 숨기고, 다른 사람이 사진 한 장만 들고 찾아가 같은 구도로
재촬영해 인증하는 위치 기반 보물찾기 앱. 프로토타입이다.

벽에 간 금, 틈 사이로 잘려 보이는 풍경처럼 **그 자리에 그 각도로 선 사람에게만 존재하는 장면**이
문제가 된다. 좌표를 알아도 각도를 못 맞추면 인증되지 않는다. 찾고 나면 근처 가게 쿠폰이 나오고,
가게는 그 쿠폰이 실제로 쓰였을 때만 비용을 낸다.

## 열어 보기

브라우저에서 `index.html` 을 열면 지도 화면부터 시작한다. 설치할 것은 없고, 지도 타일과
판정 엔진(OpenCV.js)을 내려받기 위해 인터넷 연결이 필요하다.

```
1. 지도에서 문제 선택
2. 상세 화면 → [찾으러 가기]
3. 인증 화면 → [저장된 사진으로 도전 (테스트)] 로 사진 넣기
4. 판정 통과하면 → [도감 보러 가기]
```

- 숫자와 처리 로그를 보려면 주소 뒤에 `?dev=1` 을 붙이거나 버전 표기를 일곱 번 누른다.
- 탭을 닫고 새로 열면 처음 상태로 돌아간다.
- `tools/matching-engine.html` 은 사진 두 장을 직접 비교해 보는 개발용 도구다.

## 판정 방식

사진이 비슷한지가 아니라 **같은 자리에서 같은 각도로 찍었는지**를 본다.

1. 두 사진에서 ORB 특징점을 뽑아 대조하고, 비율 검정으로 우연한 짝을 거른다
2. RANSAC으로 기하 검증을 걸어 하나의 변환으로 설명되는 점만 남긴다 — 이 개수가 "같은 대상"
3. 그 변환으로 원본 네 모서리를 옮겨 사다리꼴 찌그러짐을 잰다 — 이 값이 "각도 차이"

두 축을 합쳐 네 구간(인증 / 부분 / 근접 / 실패)으로 판정한다. 각도 허용치가 곧 난이도다.
판정은 단말에서 돌고 사진은 서버로 나가지 않는다. 자세한 것은
[`docs/모듈1_사진인식_구조.md`](docs/모듈1_사진인식_구조.md).

## 구조

```
index.html        지도 (홈, 하단 4탭 + 출제 버튼)
detail.html       문제 상세 · 힌트 · 겹쳐보기
camera.html       촬영 · 인증 · 판정
create.html       출제 (등록 전 사전 검사)
collection.html   도감 · 쿠폰 · 나
api.js            데이터 단일 통로 — 화면은 직접 통신하지 않는다. 임계값 CONFIG도 여기
engine.js         판정 엔진 한 벌 (숫자 임계값 하드코딩 없음)
ui.css            디자인 토큰 (shadcn 시맨틱 이름, 다크/라이트)
tools/            개발용 매칭 엔진 페이지
docs/             설계와 모듈별 기록
```

화면은 `api.js` 를 통해서만 데이터를 읽는다. 지금은 내장 데이터를 돌려주고, 서버가 생기면
이 파일만 바꾸면 화면 코드는 그대로 둘 수 있다.

## 지금 상태

- 서버가 없다. 난수 발급과 서버 검증은 화면상 연출이고, 판정은 실제로 돌아간다.
- 화면 사이의 상태는 탭이 살아 있는 동안만 유지된다 (서버 자리를 대신하는 임시 장치).
- 임계값은 실험값이라 현장 측정 후 조정해야 한다.
- 문서 일부는 공개본에서 부정행위 방어의 세부를 덜어냈다. 해당 위치에 안내를 달았다.
